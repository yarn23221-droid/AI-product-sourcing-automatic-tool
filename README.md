# AI 기반 해외상품·경쟁가격 분석 자동화

크로켓(네이버 계열 셀러 운영사) 인턴 재직 중 실제로 수행했던 업무 프로세스 중 **반복·계산·분류 구간만**
자동화하고, **"상품 발굴"은 사람이 그대로 맡는 구조**로 재현한 포트폴리오 프로젝트입니다.
API 키나 외부 계정 없이 로컬 Python 스크립트 실행만으로 동작합니다.

> ⚠️ 이 저장소에는 실제 크로켓 사내 데이터(매입가, 내부 코멘트, 실제 상품 리스트 등)가 전혀 포함되어
> 있지 않습니다. 모든 샘플 데이터는 가상 브랜드/가상 제품으로 새로 만든 것입니다.

## 1. 문제 정의

| 기존 수작업 | 이 프로젝트가 자동화한 부분 |
|---|---|
| 상품 찾기 (유튜버/베스트 모니터링) | **자동화하지 않음** — 사람이 계속 담당 (AI가 대체할 수 없는 영역) |
| 여러 판매사이트 확인 → 제품명/옵션/가격 입력 | 사람이 조사한 값을 엑셀 입력 시트에 기록 (API 미사용) |
| 수요 발생 이유 조사 | 자동: 커뮤니티 텍스트 → 카테고리 분류 (키워드 규칙) |
| 경쟁가격 비교 | 자동: 채널별 최저가 계산 |
| 타겟 가격 판단 | 자동 제안(휴리스틱) + 사람 최종 검수 |
| 엑셀에 정리 | 자동: 서식·수식·조건부서식이 적용된 결과 리포트 생성 |

## 2. 데이터 원칙

1. 실제 회사 내부 데이터는 절대 사용하지 않습니다. 샘플은 전부 가상 브랜드/가상 상품입니다.
2. 카테고리는 **디지털가전**으로 한정합니다. (담배 등 소매가가 법으로 고정된 품목은 "여러 채널 가격
   비교"라는 핵심 메커니즘이 성립하지 않아 제외했습니다.)
3. 외부 API를 전혀 호출하지 않습니다. 네이버 오픈API, 검색량 조회 API 등을 쓰지 않고, 채널별
   가격은 **사람이 직접 조사해서 숫자로 입력**하는 것이 기본 흐름입니다. 프로그램은 그 값으로
   계산·분류·리포트 생성만 자동으로 수행합니다.
4. 모르는 값은 추측해서 채우지 않습니다. 채널 가격이나 수요 텍스트 파일이 비어 있으면 결과 시트에
   "확인 필요"/"미입력"으로 명시하고, 값을 임의로 지어내지 않습니다.

## 3. 데이터 수집 기준

- **상품 후보 소스 (유튜버 채널 11개, 최근 1개월 영상, 국내 정식 출시 제품은 1차 제외)**
  이스모, 아론황, 잇섭, 테크몽, 디에디트, 주연, 뻘짓연구소, 엠알, 언더케이지, 귀곰, 눈쟁이
- **직구수요 발생사유 텍스트 소스 (커뮤니티 6개, 신제품/뉴스 게시판)**
  퀘이사존, 루리웹, 쿨엔조이, 보드나라, 케이벤치, 아마존 뉴릴리즈

## 4. 프로젝트 구조

```
croquet-ai-automation/
├── README.md
├── requirements.txt
├── data/
│   ├── input/input_template.xlsx      # 입력 템플릿 (가상 상품 15건 예시 포함)
│   ├── demand_texts/*.txt             # 커뮤니티 수요 텍스트 샘플
│   └── output/result_*.xlsx           # 실행 결과 (매 실행마다 새로 생성, git에는 커밋 안 함)
├── src/
│   ├── build_input_template.py        # 입력 템플릿 생성 (안내 시트 + 입력 시트)
│   ├── price_analysis.py              # 최저가 계산 / 타겟가 휴리스틱
│   ├── demand_classifier.py           # 직구수요 발생사유 키워드 분류
│   ├── excel_builder.py               # 결과 엑셀 생성 (수식/서식/조건부서식)
│   └── main.py                        # 전체 파이프라인 실행
└── examples/
    └── before_after.md                # 수작업 대비 소요시간/정확도 비교 기록 틀
```

## 5. 설치 및 실행 방법

```bash
# 1) 패키지 설치 (pandas, openpyxl만 필요 — API 클라이언트 없음)
pip install -r requirements.txt

# 2) (선택) 새 빈 템플릿이 필요하면 실행 — 이미 채워진 예시 데이터를 덮어씁니다.
python src/build_input_template.py

# 3) data/input/input_template.xlsx의 '입력' 시트에 상품 정보를 채워 넣기
#    (이미 가상 상품 15건이 예시로 채워져 있어 바로 3번을 실행해도 결과를 확인할 수 있습니다)

# 4) 파이프라인 실행
python src/main.py
```

실행하면 `data/output/result_YYYYMMDD_HHMM.xlsx`가 생성됩니다. "결과" 시트와 "요약" 시트가 들어
있습니다.

각 모듈은 아래처럼 단독으로도 실행해서 로직만 확인할 수 있습니다.

```bash
python src/price_analysis.py       # 최저가/타겟가 로직 자체 테스트
python src/demand_classifier.py    # 수요텍스트 분류 자체 테스트
```

## 6. 처리 로직

- **판매채널별 최저가**: 채널1~3 중 이름과 가격이 모두 채워진 것만 모아 최솟값을 계산합니다.
- **가격차이(%)**: `(크로켓 가격 − 판매채널별 최저가) / 판매채널별 최저가`. 파이썬에서 계산한 숫자를
  박아 넣지 않고 **실제 엑셀 수식**(`=IF(...)`)으로 기입하므로, 나중에 값을 고치면 자동 재계산됩니다.
- **타겟가 제안**: 크로켓 가격이 최저가보다 5% 넘게 비싸면 최저가+2%를, 크로켓 가격이 없으면
  최저가+3%를 초기 타겟가로 제안하고, 그 외(±5% 이내 또는 이미 더 저렴)에는 현재가 유지를 제안합니다.
  각 판단 근거는 타겟가 셀의 **엑셀 메모(코멘트)**로 남깁니다.
- **직구수요 발생사유 분류**: 지정된 텍스트 파일을 읽어 가격 / 국내 미출시·미판매 / 성능·기능 /
  디자인·휴대성 / 브랜드 신뢰도·입소문 / 국내 A/S 불만, 6개 카테고리 키워드로 분류합니다. (선택 확장:
  `ANTHROPIC_API_KEY` 환경변수가 있으면 Claude API로 더 정교하게 분류를 시도하고, 실패하거나 키가
  없으면 자동으로 키워드 규칙으로 돌아갑니다 — 이 확장 없이도 항상 동작합니다.)

## 7. 한계 (Limitations)

- **타겟가 로직은 실제 매입 원가 데이터가 없는 상태에서 만든 휴리스틱(경험적 규칙)입니다.**
  "채널 최저가 대비 몇 % 수준"이라는 단순 규칙일 뿐, 원가·마진·프로모션 등을 반영한 정밀한 가격
  책정이 아닙니다. 최종 가격 결정에는 반드시 사람의 검수가 필요합니다.
- 직구수요 발생사유 분류는 키워드 매칭 기반이라, 문맥을 정교하게 이해하지는 못합니다. 문장에 카테고리
  키워드가 없으면 "분류 불가(수동 확인 필요)"로 표시됩니다.
- 채널 가격/크로켓 가격은 사람이 직접 조사해 입력해야 하며, 이 프로그램은 실시간 가격을 스스로
  수집하지 않습니다. (월간검색량 자동 조회, 실시간 웹 스크래핑/오픈API 연동, 웹앱 배포는 이번
  범위(MVP) 밖입니다.)

## 8. 검증

가상 상품 15건(무선청소기, 커피머신, 공기청정기, 전동칫솔, 헤어드라이어, 로봇청소기, 스마트워치,
가습기, 게이밍마우스, 전기그릴, 미니냉장고, 전기포트, 블루투스이어폰)으로 `python src/main.py`를
엔드투엔드 실행했고, LibreOffice로 결과 파일을 열어 모든 수식이 실제로 재계산되는지 확인했습니다.

- 처리된 상품: 15건 (에러로 건너뛴 행 0건)
- 수식 오류(`#VALUE!` 등): **0건**
- 요약 시트 "가격 조정 필요 상품 수" 수식(`COUNTIF`) 결과: 5건 (수동 검산과 일치)
- 채널가/크로켓가격/수요텍스트파일이 비어 있거나 잘못된 파일명을 가리키는 경우(테스트용으로 일부러
  포함) 모두 예외 없이 "미입력"/"확인 필요"/"파일 없음(확인 필요)"로 안전하게 처리됨을 확인했습니다.

## 9. 이번 범위에서 제외 (MVP 밖)

월간검색량 자동 조회, 실시간 웹 스크래핑/오픈API 연동, 웹앱/대시보드 배포, 담배 등 타 카테고리 확장.
(`src/`의 모듈이 분리되어 있어 나중에 필요하면 이런 확장을 붙이기 쉬운 구조입니다.)
