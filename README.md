# AI 기반 해외상품·경쟁가격 분석 자동화

크로켓(네이버 계열 셀러 운영사) 인턴 재직 중 실제로 수행했던 "해외 인기 상품을 찾아 국내 판매
후보로 검토하는" 업무 프로세스를, **반복 조사·대조 구간만 자동화**하고 **"최종 상품 확정"은
사람이 맡는 구조**로 재현한 프로젝트입니다. API 키 없이, 실제 공개 사이트(네이버 베스트,
크로켓)의 공개 데이터를 그대로 사용합니다.

## 1. 이 프로그램이 하는 일

| 단계 | 자동화 여부 |
|---|---|
| 네이버 베스트에서 카테고리별(일간/주간) 상위 상품 리스트업 | ✅ 자동 (내부 공개 API 직접 호출) |
| 카테고리 간 중복 제거 / 최근 10일 이내 재등록 상품 제외 | ✅ 자동 |
| 국내 대기업 브랜드 1차 제외 (해외 후보만 남기기) | ✅ 자동(휴리스틱) — 사람 최종 확인 필요 |
| 크로켓 등록여부 / 등록되어 있다면 가격(배송비 포함)·링크 조회 | ✅ 자동 (헤드리스 브라우저로 실제 검색 흉내) |
| 브랜드/제품명(옵션명 제외)/제품번호 정리 | ✅ 자동(휴리스틱) — 특히 브랜드는 사람 최종 확인 필요 |
| 네이버 가격비교(해외직구 탭)로 구매/찜/리뷰수 기반 수요 등급 판단 | ❌ 사람이 직접 조사 (아래 4번 참고) |
| 옵션(사이즈/컬러/용량 카테고리), 크로켓 외 판매채널 2·3번째 | ❌ 사람이 직접 조사 |
| 유튜브 링크 기반 상품 발굴 | ❌ 사람이 계속 담당 (AI가 대체할 수 없는 영역) |

## 2. 왜 일부는 자동화하지 않았나 — 네이버쇼핑 봇 차단

네이버 베스트(`snxbest.naver.com`)와 크로켓(`croket.co.kr`)은 공개된 내부 API를 그대로 호출해
자동화했지만, **네이버쇼핑 일반검색/가격비교(`search.shopping.naver.com`)는 자동 접근을 명시적으로
차단**하고 있습니다 (`curl`로도, 실제 헤드리스 브라우저로도 즉시 "비정상적인 접근이 감지되어
접속이 제한되었습니다" 응답을 받음). 이런 명시적 차단을 우회하는 시도(IP 우회, 탐지 회피 등)는
정책상 하지 않았습니다. 그래서 이 페이지를 봐야 하는 항목(직구수요 존재여부 등급, 채널별 가격비교)
은 사람이 직접 조사해서 채웁니다.

## 3. 데이터 원칙

1. 실제 회사 내부 데이터(매입가, 내부 코멘트 등)는 이 저장소 어디에도 없습니다.
2. 카테고리는 디지털/가전으로 한정하고, 그중에서도 "순수 기기"만 다룹니다 — 게임 코드처럼 실물이
   아닌 상품이 섞여 나오는 카테고리(게임기/타이틀), 소프트웨어 카테고리는 수집 대상에서 제외합니다.
3. 모르는 값은 추측해서 채우지 않습니다. 자동으로 알아낼 수 없는 항목은 "확인 필요"로 남깁니다.
4. 국내/해외 브랜드 판별, 크로켓 상품명 매칭은 모두 키워드/토큰 겹침 기반 **휴리스틱**입니다.
   완벽하지 않으므로 최종 확정 전 사람의 확인이 필요합니다.

## 4. 프로젝트 구조

```
croquet-ai-automation/
├── README.md
├── requirements.txt
├── data/
│   ├── output/candidates_*.xlsx   # 실행 결과 (매 실행마다 새로 생성, git에는 커밋 안 함)
│   └── state/listed_products_history.json  # 10일 중복 제외용 리스트업 이력 (로컬 상태, git에는 커밋 안 함)
└── src/
    ├── naver_best_client.py      # 네이버 베스트 카테고리/랭킹 API 호출
    ├── domestic_brand_filter.py  # 국내 대기업 브랜드 1차 필터
    ├── listing_history.py        # 10일 이내 재등록 상품 제외 (로컬 이력 관리)
    ├── croket_client.py          # 크로켓 등록여부/가격/링크 자동 조회 (Playwright)
    ├── title_parser.py           # 상품명에서 브랜드/제품명/제품번호 추출 (규칙 기반, 선택적으로 Claude API)
    └── discover_candidates.py    # 전체 파이프라인 실행
```

## 5. 설치 및 실행

```bash
# 1) 패키지 설치
pip install -r requirements.txt

# 2) Playwright가 쓸 브라우저 설치 (최초 1회만)
python -m playwright install chromium

# 3) 실행
python src/discover_candidates.py
```

실행하면 `data/output/candidates_YYYYMMDD_HHMM.xlsx`가 생성됩니다. 브랜드/제품명/제품번호/
크로켓 정보/채널1은 자동으로 채워지고, 사람이 채워야 하는 항목(옵션, 채널2·3, 직구수요
존재여부/발생사유)은 빈칸으로 남아 있습니다 (직구수요 존재여부 헤더 셀에 판정 기준이 메모로
달려 있습니다).

`src/discover_candidates.py` 상단의 `NON_DEVICE_SUBCATEGORY_NAMES`(제외할 카테고리 목록)와
`TOP_N_PER_CATEGORY`를 조정해 대상 카테고리/수집 개수를 바꿀 수 있습니다.

## 6. 처리 로직

- **네이버 베스트 수집**: `snxbest.naver.com`의 공개 내부 API로 하위 카테고리 목록과 랭킹(일간/주간)
  을 그대로 가져옵니다. 상품명, 링크, 가격, 할인가, 배송비, 판매처가 포함됩니다.
- **10일 이내 중복 제외**: 상품ID(`productId`) 기준으로 로컬 이력 파일에 리스트업 날짜를 기록해두고,
  최근 10일 이내 기록이 있으면 다시 후보로 올리지 않습니다.
- **카테고리 간 중복 제거**: 같은 실행 안에서 여러 카테고리에 동시에 뜬 상품은 처음 나온 것만 남깁니다.
- **국내/해외 1차 판별**: 상품명에 국내 대기업/유명 브랜드 키워드가 있으면 제외합니다. 목록에 없는
  브랜드는 전부 "해외 후보"로 남기고, 없는 걸 있다고 판단하지 않습니다.
- **크로켓 자동 조회**: 크로켓 검색은 브라우저에서 발급되는 세션 토큰이 있어야 응답하는 걸 확인해서,
  Playwright로 실제 검색 화면을 흉내냅니다. 검색어가 길면 결과가 0건으로 나오는 경우가 있어 단어
  수를 줄여가며 재시도합니다. 상품명이 같은 상품인지는 전체 문자열 일치가 아니라 **토큰(단어) 겹침
  비율**로 판단하고, 모델번호처럼 브랜드+숫자가 결합된 토큰(예: `포크6`)이 일치하지 않으면 스펙만
  같은 다른 모델을 같은 상품으로 착각하지 않도록 걸러냅니다.
- **브랜드/제품명/제품번호 정리**: "브랜드 제품명 모델번호 [프로모션 문구/옵션]" 형태가 많다는
  점을 이용해 규칙 기반으로 프로모션 문구·사이즈 접미사를 지우고 모델번호를 뽑아냅니다.
  `ANTHROPIC_API_KEY`가 설정되어 있으면 Claude API로 더 정확하게 뽑아보고, 없으면 규칙 기반으로
  동작합니다 (이 확장 없이도 항상 동작). 브랜드는 상품명에 명시되어 있지 않으면(예: PS5 -
  '소니'라는 단어 자체가 없음) 틀릴 수 있어 사람 확인이 필요합니다.

## 7. 검증하며 발견한 한계 (그대로 기록)

- 초기 버전은 상품명 전체 문자열이 정확히 일치해야 크로켓 등록 여부를 찾아서, 실제로 등록된 상품도
  놓치는 문제가 있었습니다 → 토큰 겹침 비교로 수정.
- 그 직후에는 반대로 "포크6"와 "포크7"처럼 모델번호만 다른 상품을 같은 상품으로 잘못 매칭했습니다
  (공통 스펙 숫자 때문) → 브랜드+숫자 결합 토큰만 엄격하게 비교하도록 재수정.
- 국내 브랜드 목록은 계속 보완이 필요한 상태입니다 (예: `ipTIME` 누락을 검증 중 발견해 추가함).
- 크로켓에 검색해도 실제로 없는 상품(로보락 로봇청소기 등 대형가전 계열)이 다수 있었습니다 —
  크로켓이라는 채널 자체의 상품 구성 특성으로 보이며, 프로그램 오류가 아닙니다.
- 25개 하위카테고리 × 카테고리당 3개로 실행한 소규모 테스트에서 40개 후보 중 실제 크로켓 등록
  1건을 정확히 찾아냈습니다 (2026-08-28 기준).

## 8. 이번 범위에서 제외

네이버쇼핑 가격비교 자동화(봇 차단으로 불가), 웹앱/대시보드 배포, 디지털/가전 외 카테고리 확장.
